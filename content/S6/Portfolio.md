# Le concept de l'exercice

Est attendu :

## Auto-évaluation

- quels savoir-faire je possède ;
- quelles sont leurs relations hiérarchiques (des savoir-faire) ;
- quel degré d'expertise j'ai atteint dans les savoir-faire en haut de la hiérarchie ;
- quelle sont leur relation/importance par rapport à la formation du but.

## Communication

- présentation orale ;
- sur un domaine circonscrit : l'expérience de stage / alternance ;
- structuration du contenu imposé ;
- attendus strict sur le fond ;

# Les savoir-faire

> [!info]  Définition
> "Être capable d'utiliser des connaissances (= savoir) pour créer (= faire) quel que chose"

Il faut bien différencier savoir et savoir-faire :
- **savoir :** connaître + nom (par ex. connaitre la syntaxe Java) ;
- **savoir-faire :** être capable de + verbe (par ex. être capable de coder en Java).

# Attendus

**Format :** présentation orale avec transparents de 10 à 15 minutes.

**Contenu imposé :**
- 1 transparent de garde ;
- 1 transparent d'introduction ;
- 2 séries de transparents illustrant chacune un savoir-faire en général, contenant :
	- une trace "générale", son contexte et sa description ;
	- une liste de savoir-faire élémentaires associés à la trace ;
	- pour quel(s) objectif(s) et comment ont été utilisés ces savoirs-faires (par ex. en s'appuyant sur les détails de la trace), pourquoi ces savoir-faires sont importants ;
	- un bilan, avec une auto-évaluation ;
- 1 ou 2 transparents de conclusion / perspectives.

**Au choix :** Structuration visuelle des transparents (charte graphique, illustrations).

## Structure générale

## Transparent de garde

Points essentiels :
- titre personnalité (en relation) ;
- sous-titre général (en relation avec l'exercice du portfolio) ;
- nom, prénom ;
- date ;
- éléments graphiques en relation avec le contexte (ex. logo entreprise) ;
- pas de n° de transparent.

> [!example]  Exemples de titres
> très mauvais: "Portfolio BUT3"
> Moyen: "Présentation de quelques savoir-faire développés en stage"
> Bien: "réalisation d'une application de gestion des stages"

> [!example] Exemple de sous-titres
> Moyen: "Portfolio BUT3"
> Bien: "Descriptif et bilan de savoir-faire mobilisés lors du stage de BUT3"

### Attendus de l'oral

- se présenter et remercier l'auditoire ;
- faire une micro-introduction très générale :
	- archi-nul = j'oublie et passe directement au transparent d'après ;
	- nul = "je vais parler de savoir-faire que j'ai développés en S2" ;
	- bien = "Au travers de cette présentation, je vais faire un bilan d'évolution sur quelques savoir-faire que j'ai utilisés au cours de mon stage de BUT3, plus particulièrement sur les domaines du ... et du .... Je prendrai pour cela des traces qui illustreront comment et pour quoi j'ai utilisés ces savoir-faire..."
## Introduction

**Points essentiels :**
- présenter le contexte général
	- les objectifs du stage ;
	- quelles "parties" du stage sont utilisées ;
	- pourquoi ce choix ;
- présenter quels savoir-faire généraux vont être illustrés ;

**Points optionnels :**
- justifier pourquoi choisir ces savoir-faire généraux ;
- présenter la forme des transparents à suivre.

> [!example] Exemples de "pourquoi ces parties du stage"
> Mauvais : "J'ai choisi de présenter ... parce que c'est la partie sur laquelle j'ai passé le plus de temps"

## Format : séries de transparents

**Points essentiels :**
- 2 séries illustrant des savoir-faire élémentaires directement reliés à un même savoir-faire général dépendant d'un domaine ;
- domaines possibles :
	- info : dev, réseau, architecture, système, bdd, gestion projet, ... ;
	- intégration en entreprise : travail en équipe, contact/support client, ... ;
- contrainte : aborder deux domaines différents (dev & bdd, réseau & équipe, ...).

## Format : pour chaque série

**Points essentiels (dans l'ordre) :**
- 1 ou 2 transparents présentant :
	- une trace "générale" avec n°, titre, si besoin légende ;
	- son contexte (quelle partie du stage, objectifs généraux, ...) ;
	- les savoir-faire élémentaires qui vont être décrits ;
- 1, 2, ... transparents avec :
	- des parties/détails de la trace ;
	- quels savoir-faire élémentaires sont impliqués pour obtenir cette partie, comment et dans quel(s) but(s) ;
	- pourquoi ces savoir-faire élémentaires sont importants ;
- 1 ou 2 transparent de bilan :
	- rappel de savoir-faire élémentaires et du savoir-faire général ;
	- évaluation "argumentée" de l'évolution **par rapport au BUT** dans le savoir-faire général (par ex. de 0 à moyen, pas d'évolution car déjà bien connu, ...).

**Remarques :**
- trace **LISIBLE** (ne pas hésiter à zoomer dessus pour bien la décrire) ;
- décrire de façon globale la trace (contexte, parties importantes, ...) ;
- liste des savoir-faire élémentaires abordés :
	- donner une courte explication si pas compréhensible par un non spécialiste;
	- expliquer en quoi ils sont en relation avec la trace.
- Comment on été utilisés les savoir-faire, décrire un processus en vue d'atteindre un objectif et la qualité du résultat ;
- les parties de trace utilisées comme support peuvent :
	- décrire le processus (par ex. le schéma) ;
	- être l'objectif (par ex. maquette, copie d'écran, ...) ;
- pourquoi les savoir-faire choisis sont importants :
	- quels impacts sur le résultat du stage/alternance cela aurait et/ou a eu de savoir-faire et/ou ne pas savoir faire ?
	- (optionnel) quels impacts sur un travail futur.

> [!example] Exemples sur la description + contexte de la trace :
> Archi-nul : "Cette trace est une interface graphique en mode console, lorsque le contrôleur demande d'afficher pour la première fois l'état de l'application ..."

> [!tip] Conseils
> - le plus simple : donner l'objectif puis énumérer les étapes pour l'atteindre : "Pour faire, ..., j'ai commencé par ... afin de mettre en place ... . Ensuite, j'ai pu ... etc." ;
> - le plus complique : décrire en quoi la mise en relation de savoir-faire permet d'atteindre l'objectif : "réaliser ... nécessite de savoir-faire ... , et ... . En effet, le premier permet de ... alors que le second implique de ... . Enfin, le dernier conduit à ..." ;
> - toujours conclure sur la qualité de réalisation de l'objectif : atteint ou pas/partiellement, facilement/difficillement

## Conclusion / perspectives

### Bilan

- ne pas oublier de résumer : 
- continuer avec les critères qui servent à évaluer son évolution. Exemples :
	- la qualité du résultat du stage/alternance ;
	- l'avis de l'encadrant entreprise ;
	- les notes obtenues dans les matières associées ;
	- niveau > 0 préalable ;
	- autres projets (persos, Tps, ...).

### Conclusion

- reprendre les éléments clefs des bilans :
	- savoir-faire généraux abordés ;
	- niveaux atteints ;
- tirer des explications/conclusions sur différents points, exemples :
	- quels aspects du stage ont freiné / accéléré l'évolution de niveau ;
	- quels autres "projets" ont participé à l'évolution et comment ;
	- quels moyens pour s'améliorer ;
- donner des perspectives (ce qu'on aimerait faire à l'avenir), exemples :
	- type de stages/projets ;
	- autres façons d'organiser le travail ;
	- autres contraintes techniques.
