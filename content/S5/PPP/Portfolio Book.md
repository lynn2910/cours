# Définition : un mot pour deux réalités

## Portfolio de compétences

Document obligeant à adopter une approche réflexive et analytique sur ses savoirs et savoir-faire.

## Portfolio de présentation / book

Document vitrine des graphistes, informaticiens, etc.
- client ou recruteur pouvant visualiser leurs productions ;
- visée démonstrative : illustrer son expertise afin de promouvoir ses activités ;
- nombre restreint d'entrées ;
- valorisation des compétences acquises pour mettre l'accent sur ses points forts ;
- présentation de ses meilleures réalisations.

---
# Travail et objectif

Créer un portfolio mettant en avant ses travaux et savoir-faire.

## Contexte

En vue du stage de S6 ou de la recherche d'un nouvel apprentissage ou d'un emploi.

## Objectif

Donner envie à un RH de vous accorder un entretien voir un poste, après avoir consulté votre portfolio.

## Forme

Présenté via un site web **responsive**.

## Date de rendu

À rendre au plus tard lundi 1er décembre à 23 h 59 sur Moodle, en déposant le lien du portfolio.

# Intérêts d'un site pour son portfolio

Cela permet de :
- démontrer ses savoir-faire dans le web ;
- possibilité d'acquérir des connaissances ;
- possibilité de faire évoluer son portfolio sur des années ;
- preuve de son intérêt pour un domaine avec lequel on a peu d'expérience.

> [!tip] C'est une tendance de plus en plus importante

# Façons de créer son site : trois solutions

## Coder son site par soi-même de A à Z

C'est un investissement en temps, même pour un site vitrine sans trop d'effets et en s'inspirant fortement de l'esthétique de sites existants.

Obligatoire pour les personnes :
- désirant travailler dans le développement web ;
- et/ou candidatant pour effectuer un travail dans le développement web (apprentissage, stage, ou emploi).

> [!tip] Cette solution est conseillée

## S'appuyer sur un CMS

Aisé de créer, gérer et modifier un site, y compris l'optimisation pour les moteurs de recherche.

Indispensable, pour un futur informaticien, de choisir un CMS open source pour avoir accès au code.

Choix nécessitant de posséder des notions de HTML, CSS, PHP et JavaScript

## Utiliser un constructeur de site web

Créer un site sur la base d'un modèle et de fonctions glisser-déposer.

Souvent, proposition d'un plan d'hébergement et d'un nom de domaine.

# Ergonomie, usabilité

Faciliter la lisibilité et la navigation pour permettre de vite trouver l'essentiel.

## Travail de mise en valeur

**Faciliter la lisibilité :** **mise en valeur de l'essentiel et structuration du texte**
- hiérarchie visuelle avec des titres pertinents et des sous-titres ;
- paragraphes organisés logiquement (thématiquement, chronologiquement, du plus simple au plus complexe, ...) ;
- premier paragraphe essentiel : généralement descriptif : résumé de la page ;
- idée principale d'un paragraphe au début de celui-ci ;
- une seule idée par paragraphe ;
- paragraphes concis.

**Utilisation réfléchie** des couleurs, caractères gras, tableaux, etc.

## Fluidifier la navigation

**Fluidifier la navigation :**
- chaque élément du menu doit être clair et précis ;
- compréhension immédiate des utilisateurs ;
- accès rapide à l'information souhaitée ;
- éléments interactifs suffisamment grands et contrastés ;
- liens signalés clairement — rien d'autre de souligné dans un site ;
- libellés des menus explicités ;
- pas trop d'éléments dans le menu principal — menu déroulants possibles ;
- menu flottant - surtout si le site est long ;
- respect des standards d'accessibilité web : site navigable à l'aide d'un clavier et compatible avec des lecteurs d'écran.

# Optimiser la vitesse de votre site : téléchargeable en moins de 3 secondes

- Optimisation et minification du code ;
- choix de l'hébergeur ;
- choix et l'installation d'un CDN ;
- activation de la mise en cache pour stocker les données à part ;
- configuration du *lazy load* pour les grosses pages ;
- compression d'images — et la suppression de celles qui sont superflues.
### Mesurer la vitesse du site

> [!example] Ex. avec PageSpeed Insights qui propose des pistes d'améliorations.

## Éviter tout bug

Liens cassés ou bouton ne marchant pas : **rédhibitoire**.

**Vérification** du fonctionnement.

# Rubriques

## À propos

Brève présentation à la première personne le plus souvent.

Ton sérieux : site pour des recruteurs, des clients.

Clins d'œil possibles.

Style pour faire passer votre personnalité :
- choix des mots ;
- façons d'aborder des sujets ;
- etc.
## Présentation de vos projets : la rubrique phare

Présentation concise, mais claire pour mettre en valeur vos capacités — projets bien réalisés uniquement :
- nom du projet ;
- brève description : objectif et utilité ;
- technologies utilisées ;
- capture(s) d'écran ou vidéo de démonstration ou mieux, car prouvant que ce n'est pas une maquette fictive : lien vers votre projet (URL du projet ou lien repo Github ou Gitlab, …) ;
- fonctionnalités principales si possible.

Possible de compléter pour certains projets :
- les défis rencontrés et les solutions apportées ;
- votre rôle dans le projet si un projet d'équipe ;
- voire les évolutions possibles.

## Compétence : une rubrique dispensable mais pratique

- technologies utilisées précisées pour les projets mais rubrique pratique car synthèse rapide à lire ;
- possibilité d'indiquer des compétences autres : "gestion de projet", etc. ;
- ou des qualités personnelles telles que "gestion du stress", etc.

## Contact : une rubrique essentielle

Le formulaire de contact est obligatoire.

Ajouts possibles :
- adresse mail ;
- et/ou un numéro de téléphone ;
- GitHub/Gitlab obligatoire — voir RSP ;
- message d'accueil ;
- etc.

> [!tip] Ajouter un petit texte sur le traitement de données quand on nous contacte.

Le **CV** doit être **TÉLÉCHARGEABLES**, mais pas forcément une rubrique :
- aisément trouvable ;
- téléchargeable au format `.pdf` ;
- portfolio cité dans votre CV avec un lien pour le trouver ;
- idéal : même style visuel que le site.

# Ciblage difficile

## Qui lire votre site ? Quasi impossible à savoir

Donc impossible de cibler précisément un lectorat. 

Faire un grand écart pour parler à tout un chacun :
- des spécialistes de l'informatique : "Java", "Git", "Framework", etc. : sens clair et termes attendus ;
- des non-spécialistes perdus à cause d'eux...


**Termes techniques, mais au bon endroit :**
- peu, voire pas du tout, dans la présentation ;
- présents dans la présentation des projets : mise en avant de vos capacités ;
- mais projet compréhensible par tous : description claire et sans verbiage ; 
- termes présents dans la rubrique "Compétences"

# Critères de notation

- ergonomie, usabilité
- esthétique satisfaisante et un tant soit peu personnelle : Animations et effects visuels possible, mais navigation et lisibilité non gênées : Design clair et ergonomique pour offrir une bonne expérience utilisateur

## Contenu clair, précis, concis, utile

- "A propos" avec un bref texte de présentation
- "Projets" — dont le stage / apprentissage de S4 / S6 — présentés clairement et brièvement et mettant en valeur vos capacités 
- Compétences techniques et personnelles présentes
- Formation présentée (dans une rubrique à part ou dans "A propos")
